# School tenancy database upgrade

The schema adds organizations and memberships, assigns every existing course to a generated `legacy-school` organization, and backfills owner, instructor, and learner memberships from the existing course relationships. Existing courses, enrollments, progress, submissions, and certificates are retained. The migration intentionally does not seed a real school or modify a live database.

For a new installation, use the fresh-install procedure in the repository README. For an existing installation, first take and verify a database backup, then review and apply `prisma/migrations/20261015010000_school_tenancy/migration.sql` against that legacy schema with `psql -v ON_ERROR_STOP=1 -f ...`. This migration is the schema change and the required data backfill. If the deployment is adopting Prisma migration tracking for the first time, register the successfully applied migration with `pnpm exec prisma migrate resolve --applied 20261015010000_school_tenancy`; later releases can use `pnpm exec prisma migrate deploy`. Do not use `prisma db push` as an upgrade mechanism for an existing installation: it does not run the legacy membership backfill. Verify the resulting `Organization`, `OrganizationMembership`, and `Course.organizationId` records before enabling tenant-facing routes.

The isolated migration regression requires `TEST_TENANCY_DATABASE_URL` to point to a disposable PostgreSQL database named exactly `school84_tenant_test`. It creates and drops only a uniquely named temporary schema inside that database. Run it with `pnpm test:tenant`; it never reads `DATABASE_URL`.
